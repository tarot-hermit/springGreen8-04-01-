# SpringGreen8 발표용 PPT 제작 브리프

## 이 파일의 용도
- Claude Desktop에 이 파일을 그대로 첨부하거나 복붙해서 발표용 PPT 초안을 만들기 위한 문서다.
- 발표 흐름, 슬라이드 구성, 핵심 문장, 시각 방향, 데모 포인트를 한 번에 정리했다.
- 기준 발표 시간은 7~10분으로 가정했다.

## 프로젝트 한 줄 소개
Spring MVC 기반의 영화·드라마·애니메이션 탐색/검색/리뷰 커뮤니티 서비스로, TMDB API와 연동해 콘텐츠 정보를 제공하고 사용자 리뷰, 댓글, 찜, 컬렉션, 관리자 기능까지 구현한 웹 프로젝트.

## 프로젝트 핵심 요약
- 프로젝트명: `SpringGreen8`
- 성격: 영화/드라마/애니메이션 콘텐츠 탐색 및 리뷰 커뮤니티
- 개발 형태: Java Spring MVC 웹 프로젝트
- 주요 기술:
  - `Java 11`
  - `Spring MVC 4.3`
  - `JSP + JSTL + Bootstrap`
  - `MyBatis`
  - `MySQL`
  - `RestTemplate`
  - `TMDB API`
  - `YouTube fallback`
- 핵심 기능:
  - 영화, 드라마, 애니메이션 탐색
  - 콘텐츠 검색, 인기 검색어, 최근 검색어
  - 상세 페이지, 예고편, 출연진, 스태프, 키워드, OTT 제공처
  - 회원가입, 로그인, 이메일 인증, 프로필 수정, 비밀번호 변경
  - 리뷰, 댓글, 좋아요, 신고, 블라인드 처리
  - 찜, 봤어요, 컬렉션
  - 관리자 대시보드, 회원/리뷰/신고 관리

## 발표에서 강조할 포인트
- 단순 조회형 프로젝트가 아니라 `탐색 + 검색 + 커뮤니티 + 관리자 기능`까지 연결된 서비스라는 점
- 외부 API 데이터를 가져오는 것에서 끝나지 않고, `검색 품질`, `예고편 fallback`, `입력 검증`, `관리자 공통 데이터 주입`처럼 실제 서비스 완성도를 높였다는 점
- 최근 개선 사항이 명확하다는 점
  - 검색어 `#`, 공백, 페이지 이동 이슈 수정
  - 최근 검색어 중복 적재 방지
  - 영화 예고편 fallback 보강
  - 영화 상세 키워드 섹션 연결
  - 검증 규칙 통합
  - XSS/SQL 과탐 완화
  - 비밀번호 변경 UI 연결

## 예고편 검색 알고리즘 설명 포인트
- 예고편은 단순히 TMDB 영상 목록을 그대로 출력하지 않고, `여러 단계의 fallback 구조`로 찾는다.
- 기본 순서는 `TMDB 한국어 영상 조회 -> TMDB 영어 영상 조회 -> 저장된 YouTube fallback 캐시 조회 -> YouTube 검색 fallback`이다.
- YouTube fallback에서는 제목 후보를 기반으로 여러 검색어를 만들고, `official trailer`, `teaser`, `preview`, `시즌명` 같은 패턴을 함께 사용한다.
- 후보 영상은 `쇼츠`, `리액션`, `리뷰`, `OST`, `오프닝`, `클립`, `씬 영상`처럼 예고편이 아닌 결과를 우선 제외한다.
- 남은 후보는 `제목 일치`, `채널 일치`, `official 여부`, `trailer/teaser 여부`, `시즌 일치` 점수로 정렬해 상위 영상만 선택한다.
- 가능하면 `임베드 가능 여부`, `공개 상태`, `한국(KR) 재생 가능 여부`까지 확인해 실제로 재생 가능한 영상만 남긴다.
- 최종 결과는 캐시에 저장해 같은 콘텐츠에서 반복 조회 시 속도와 안정성을 높인다.
- 드라마는 `선택한 시즌 -> 시즌 1 -> 시리즈 전체 영상` 순으로 추가 fallback이 동작한다.

## PPT 톤앤매너 가이드
- 전체 톤: 깔끔한 웹 서비스 발표 스타일
- 컬러: 흰색 배경 + 포인트 컬러 `#28a745` 또는 `#ff2f6e`
- 슬라이드 수: 10장 내외
- 각 슬라이드는 문장보다 `짧은 핵심 문구 + 화면/흐름 중심`
- 가능하면 실제 프로젝트 화면 캡처를 3~5장 정도 배치

## 추천 슬라이드 구성

### 1. 표지
- 제목: `SpringGreen8`
- 부제: `영화·드라마 탐색과 리뷰를 결합한 콘텐츠 커뮤니티 서비스`
- 넣을 내용:
  - 팀명 또는 발표자명
  - 개발 기간
  - 사용 기술 키워드
- 시각 요소:
  - 메인 홈 화면 캡처 또는 대표 영화 상세 화면 캡처

### 2. 프로젝트 기획 배경
- 제목: `왜 이 서비스를 만들었는가`
- 핵심 메시지:
  - OTT와 영화 정보가 분산되어 있어 원하는 콘텐츠를 찾기 불편함
  - 단순 검색뿐 아니라 리뷰와 사용자 반응까지 함께 보고 싶음
  - 콘텐츠 탐색 경험을 한 곳으로 묶은 웹 서비스를 목표로 함
- 키워드:
  - 탐색
  - 검색
  - 리뷰
  - 커뮤니티

### 3. 서비스 개요
- 제목: `서비스 개요`
- 핵심 내용:
  - 영화, 드라마, 애니메이션을 한 서비스에서 탐색
  - 상세 페이지에서 예고편, 출연진, 키워드, OTT 정보 확인
  - 회원은 리뷰, 댓글, 찜, 컬렉션 기능 사용 가능
- 시각 요소:
  - 사용자 흐름 1장짜리 다이어그램
  - 홈 -> 검색 -> 상세 -> 리뷰 작성

### 4. 기술 스택과 구조
- 제목: `기술 스택 및 시스템 구조`
- 핵심 내용:
  - Frontend: JSP, JSTL, Bootstrap, jQuery
  - Backend: Spring MVC, Java 11
  - Data: MyBatis, MySQL
  - External API: TMDB, YouTube fallback
- 구조 예시:
  - Controller
  - Service
  - DAO
  - Mapper
  - JSP View
- 발표 멘트 포인트:
  - 전통적인 Spring MVC 구조로 역할 분리를 명확히 함

### 5. 핵심 기능 1 - 콘텐츠 탐색
- 제목: `핵심 기능 1. 콘텐츠 탐색`
- 핵심 내용:
  - 인기 영화, 현재 상영작, 트렌딩, 개봉 예정작 제공
  - 영화/드라마/애니메이션 탭 분리
  - 장르별 탐색 지원
- 시각 요소:
  - 홈 화면 캡처
  - 영화 리스트 화면 캡처

### 6. 핵심 기능 2 - 검색과 상세 페이지
- 제목: `핵심 기능 2. 검색과 상세 정보`
- 핵심 내용:
  - 제목 검색 + 키워드 검색 fallback
  - `# 키워드` 검색 지원
  - 오타/띄어쓰기 보정 검색
  - 상세 페이지에서 예고편, 출연진, 스태프, 키워드, OTT 정보 제공
  - 예고편은 다단계 fallback과 후보 정렬 로직을 통해 안정적으로 제공
- 시각 요소:
  - 검색 화면 캡처
  - 영화 상세 페이지 캡처
- 강조 문장:
  - 단순 제목 검색이 아니라 실제 사용성을 고려한 검색 품질 개선을 반영함

### 7. 핵심 기능 3 - 사용자 기능과 커뮤니티
- 제목: `핵심 기능 3. 사용자 경험과 커뮤니티`
- 핵심 내용:
  - 회원가입, 로그인, 이메일 인증
  - 프로필 수정, 비밀번호 변경
  - 리뷰 작성, 댓글, 좋아요, 신고
  - 찜, 봤어요, 컬렉션
- 시각 요소:
  - 마이페이지 또는 리뷰 화면 캡처

### 8. 관리자 기능
- 제목: `관리자 기능`
- 핵심 내용:
  - 관리자 대시보드
  - 회원 관리
  - 리뷰 관리
  - 신고 처리
  - 인기 검색어 및 통계 확인
- 시각 요소:
  - 관리자 대시보드 캡처

### 9. 문제 해결 및 개선 사례
- 제목: `개발 중 해결한 문제`
- 추천 사례:
  - 영화 예고편이 비는 문제 -> TV와 동일한 fallback 구조 적용
  - TMDB 영상이 없을 때 YouTube fallback, 후보 필터링, 재생 가능 여부 확인까지 연결
  - 검색어에 `#` 포함 시 페이지 이동 오류 -> URL 인코딩 구조 수정
  - 페이지 이동마다 최근 검색어가 누적되는 문제 -> 1페이지 검색만 기록하도록 수정
  - 검증 규칙 불일치 -> `InputValidator` 중심으로 정리
  - XSS/SQL 과탐 -> 실제 공격 패턴 중심으로 수정
- 발표 포인트:
  - 기능 구현뿐 아니라 서비스 완성도를 높이는 유지보수성 개선을 함께 진행함

### 10. 기대 효과와 마무리
- 제목: `성과 및 향후 개선 방향`
- 성과:
  - 탐색, 검색, 상세 조회, 커뮤니티, 관리자 기능까지 하나의 서비스로 통합
  - 검색 품질과 예고편 제공 안정성 개선
  - 실제 서비스에 가까운 사용자 흐름 완성
- 향후 개선:
  - 추천 알고리즘 고도화
  - 리뷰 기반 개인화
  - UI 반응성 개선
  - 통합 테스트 및 배포 자동화

- `특히 검색 품질과 예고편 제공 안정성처럼 실제 사용자가 체감하는 부분을 계속 개선했습니다.`

## Claude Desktop에 바로 넣을 프롬프트
아래 프롬프트를 그대로 Claude Desktop에 입력하고, 이 파일을 함께 첨부하면 된다.

```text
너는 발표용 PPT 기획 전문가다.

첨부한 파일 내용을 바탕으로 프로젝트 발표용 PPT를 제작해줘.
조건은 아래와 같다.

1. 전체 슬라이드는 10장 내외로 구성해줘.
2. 발표 시간은 7~10분 기준으로 맞춰줘.
3. 결과는 슬라이드별로 아래 형식으로 정리해줘.
   - 슬라이드 번호
   - 슬라이드 제목
   - 핵심 메시지 1문장
   - 본문 bullet 3~5개
   - 화면에 넣을 추천 시각 요소
   - 발표자가 말할 멘트 2~4문장
4. 발표 자료 톤은 깔끔하고 실무형 프로젝트 발표 느낌으로 만들어줘.
5. 기술 나열형 PPT가 아니라, 문제 -> 구현 -> 개선 -> 결과 흐름이 살아 있게 구성해줘.
6. 검색 기능 개선, 예고편 fallback, 관리자 기능, 커뮤니티 기능은 꼭 강조해줘.
7. 예고편 부분은 단순 API 호출이 아니라, fallback 순서와 후보 필터링/정렬 기준이 보이게 설명해줘.
8. 내용은 한국어로 작성해줘.
9. 마지막에는 "실제 PPT에 넣을 최종 슬라이드 목차"만 따로 다시 정리해줘.

추가로 아래도 함께 해줘.
- 표지 슬라이드 문구 3가지 버전 제안
- 발표 마지막 장에 넣을 마무리 문장 3가지 제안
- 시연 시 가장 임팩트 있는 데모 순서 추천
```

## Claude Desktop에서 추가로 요청하면 좋은 문장
- `위 내용을 바탕으로 교수님 발표 스타일에 맞게 더 학술적이고 정돈된 문장으로 바꿔줘`
- `각 슬라이드의 문장을 더 짧게 줄여서 PPT용 텍스트만 다시 써줘`
- `발표 대본을 5분 버전과 10분 버전으로 각각 만들어줘`
- `슬라이드별로 어떤 화면 캡처를 넣으면 좋은지 체크리스트로 정리해줘`

- 이 파일을 Claude Desktop에 첨부하고 위 프롬프트를 같이 넣으면 된다.

- 발표 시간이 짧다면 슬라이드 8장 버전으로 줄여달라고 요청하면 된다.
