# SpringGreen8 Claude Desktop PPT 마스터 브리프

## 문서 목적
- 이 문서는 `Claude Desktop`이 `SpringGreen8` 프로젝트 발표용 PPT를 거의 완성형에 가깝게 생성할 수 있도록 만든 `통합 지시 문서`다.
- 기존 10장 내외 축약형 발표안이 아니라, `설명 가능한 내용은 최대한 반영하는 확장형 발표안`을 목표로 한다.
- 슬라이드 수는 고정하지 않는다.
- 발표 목적은 `프로젝트 설명`, `구현 근거 전달`, `개선 사례 강조`, `기술적 설계 포인트 설명`이다.

## 이 문서를 사용할 때의 기준
- 슬라이드 수를 억지로 줄이지 않는다.
- 기능 나열보다 `문제 정의 -> 목표 -> 구조 -> 기능 -> 알고리즘 -> 개선 -> 결과` 흐름을 우선한다.
- 발표 자료는 "웹 사이트 소개" 수준이 아니라, "설계 의도와 구현 판단이 보이는 프로젝트 발표" 수준으로 만든다.
- 특히 검색, 예고편 처리, 사용자 기능, 관리자 기능, 입력 검증, 개선 사례는 생략하지 않는다.

## 스타일 방향
- `포토폴리오(FIND_KAPOOR).pdf`를 시각적 참고 자료로 사용한다.
- 단, PDF의 텍스트를 복제하지 말고 `구성 방식`, `여백감`, `섹션 분리`, `페이지 전개 리듬`, `캡처 중심 레이아웃`만 참고한다.
- 프로젝트 내용은 반드시 `SpringGreen8` 기준으로 다시 작성한다.
- 발표 톤은 `교수님 발표 스타일 + 포트폴리오형 정리력`을 섞은 방향으로 잡는다.
- 문장은 화려한 광고 문구보다, 사실 중심의 정돈된 문체를 사용한다.

## 프로젝트 핵심 메시지
- `SpringGreen8`은 단순한 영화 정보 조회 사이트가 아니다.
- 영화, 드라마, 애니메이션을 한 서비스에서 탐색하고 검색하며, 상세 정보와 예고편, 키워드, OTT 제공처를 확인할 수 있는 콘텐츠 탐색 플랫폼이다.
- 여기에 사용자 리뷰, 댓글, 찜, 봤어요, 컬렉션, 신고, 관리자 기능까지 결합해 하나의 서비스 흐름으로 통합했다.
- 구현 이후에도 검색 정확도, 예고편 안정성, 입력 검증, 관리자 데이터 구조 등 실제 서비스 품질을 지속적으로 개선했다.

  - `영화, 드라마, 애니메이션 탐색과 커뮤니티를 연결한 웹 프로젝트`
- 넣을 내용:
  - 팀명 또는 발표자명
  - 개발 기간
  - 주요 기술 키워드
- 추천 시각 요소:
  - 메인 홈 화면
  - 또는 대표 상세 화면

### 2. 목차
- 발표 전체 흐름을 한 장에서 보여준다.
- 추천 목차:
  - 개발 배경
  - 프로젝트 목표
  - 시스템 구조
  - 핵심 기능
  - 알고리즘 및 개선 사례
  - 성과와 향후 계획

### 3. 개발 배경
- 핵심 메시지:
  - 콘텐츠 정보와 사용자 반응이 여러 플랫폼에 흩어져 있어 탐색 경험이 단절되어 있다.
- 설명 포인트:
  - 콘텐츠 정보 분산
  - 검색 한계
  - 예고편, 리뷰, 키워드, OTT 정보 통합 필요

### 4. 문제 정의
- 핵심 메시지:
  - 사용자는 단순 제목 검색이 아니라, 비교와 탐색 중심의 콘텐츠 발견 경험을 원한다.
- 설명 포인트:
  - 제목만으로 찾기 어려운 경우 존재
  - 콘텐츠를 찾은 뒤에도 추가 정보 확인 동선이 길다
  - 반응과 기록 기능까지 한 서비스에서 이어지지 않는다

### 5. 프로젝트 목표
- 핵심 메시지:
  - 탐색, 검색, 상세 조회, 사용자 반응, 관리자 운영까지 연결된 콘텐츠 커뮤니티 서비스를 구현하는 것이 목표였다.
- 설명 포인트:
  - 영화/드라마/애니메이션 통합
  - 정보 조회 + 사용자 반응 연결
  - 운영 기능 포함

### 6. 서비스 한 줄 소개와 사용자 흐름
- 핵심 메시지:
  - 사용자는 콘텐츠를 찾고, 확인하고, 기록하고, 공유하는 과정을 한 서비스 안에서 수행할 수 있다.
- 추천 흐름:
  - 홈 -> 검색 -> 상세 -> 리뷰/댓글 -> 찜/컬렉션 -> 관리자 관리
- 추천 시각 요소:

### 7. 프로젝트 범위
- 핵심 메시지:
  - 이 프로젝트는 조회 기능만이 아니라 사용자 기능과 운영 기능까지 범위를 확장한 웹 서비스다.
- 설명 포인트:
  - 사용자 화면
  - 커뮤니티 기능

  - 외부 API 연동

### 8. 기술 스택
- 설명 포인트:

- 강조 포인트:

- 테스트 또는 개선 로그 요약

## PPT 제작 시 Claude Desktop에 요구할 형식
슬라이드마다 아래 형식으로 출력하도록 요청한다.

- 슬라이드 번호
- 슬라이드 제목
- 핵심 메시지 1문장
- 본문 bullet 3~6개
- 화면에 넣을 추천 시각 요소
- 발표자가 말할 설명 멘트 2~5문장
- 필요하면 보조 메모

## Claude Desktop용 최종 프롬프트
아래 프롬프트를 그대로 사용하면 된다.

```text
너는 대학 프로젝트 발표 자료와 포트폴리오형 PPT를 함께 설계하는 전문가다.

첨부한 파일들을 모두 참고해서 SpringGreen8 프로젝트 발표용 PPT를 만들어줘.

중요 조건은 아래와 같다.

1. 슬라이드 수를 10장으로 제한하지 마.
2. 설명 가능한 내용은 최대한 포함하되, 흐름이 무너지지 않게 구성해줘.
3. 전체 흐름은 반드시 아래 순서를 기본으로 해줘.
   - 문제 정의
   - 프로젝트 목표
   - 시스템 구조
   - 핵심 기능
   - 검색 알고리즘
   - 예고편 처리 알고리즘
   - 사용자 기능
   - 관리자 기능
   - 개선 사례
   - 결과 / 한계 / 향후 계획
4. `포토폴리오(FIND_KAPOOR).pdf`는 시각적 참고 자료로 사용해줘.
   - 텍스트를 복제하지는 말고
   - 페이지 구성 방식
   - 여백감
   - 섹션 분리 방식
   - 캡처 중심 레이아웃
   - 포트폴리오형 정리감
   만 참고해줘.
5. 결과는 교수님 발표 스타일에 맞게 차분하고 정돈된 한국어로 작성해줘.
6. 기능 자랑형 문구보다 설계 의도와 개선 과정을 더 잘 드러내줘.
7. 검색 기능은 아래를 꼭 포함해줘.
   - 제목 검색
   - 키워드 검색
   - # 키워드 검색
   - 오타 / 띄어쓰기 보정
   - fallback 구조
8. 예고편 기능은 아래를 꼭 포함해줘.
   - TMDB ko-KR 조회
   - TMDB en-US 조회
   - YouTube cache fallback
   - YouTube search fallback
   - 후보 제외 규칙
   - 후보 점수화 기준
   - 재생 가능 여부 확인
   - 드라마 시즌 fallback
9. 사용자 기능과 관리자 기능을 별도 파트로 분리해서 설명해줘.
10. 최근 개선 사항과 문제 해결 사례를 충분히 반영해줘.
11. 슬라이드는 필요하면 20장 이상이어도 괜찮다.
12. 결과는 각 슬라이드별로 아래 형식으로 정리해줘.
   - 슬라이드 번호
   - 슬라이드 제목
   - 핵심 메시지 1문장
   - 본문 bullet 3~6개
   - 추천 시각 요소
   - 발표 멘트 2~5문장
13. 마지막에는 아래도 따로 정리해줘.
   - 최종 슬라이드 목차
   - 꼭 필요한 화면 캡처 목록
   - 발표 시간이 짧을 때 줄일 수 있는 슬라이드
   - 발표 시간이 충분할 때 추가하면 좋은 심화 슬라이드

추가 요청:
- 발표용으로 자연스럽게 읽히는 문장으로 써줘.
- 한 슬라이드에 메시지가 너무 많으면 적절히 분리해줘.
- 도식화가 필요한 장은 흐름도나 구조도로 제안해줘.
```

## Claude Desktop에서 후속으로 요청하기 좋은 문장
- `위 결과를 실제 PPT 문구처럼 더 짧고 강하게 다시 써줘`
- `슬라이드별 발표 대본을 10분 버전으로 만들어줘`
- `슬라이드별 발표 대본을 15분 버전으로 만들어줘`
- `각 슬라이드에 어떤 화면 캡처를 넣을지 더 구체적으로 정리해줘`
- `포트폴리오 PDF 느낌이 더 강하게 나도록 레이아웃 방향을 보강해줘`
- `발표에서 시간이 부족할 때 생략 가능한 슬라이드를 표시해줘`
