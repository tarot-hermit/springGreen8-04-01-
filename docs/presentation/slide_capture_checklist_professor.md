# SpringGreen8 슬라이드별 화면 캡처 체크리스트

## 문서 목적
- 이 문서는 교수님 발표 스타일 PPT를 만들 때 필요한 화면 캡처를 슬라이드별로 정리한 체크리스트다.
- 각 슬라이드에서 어떤 화면을 캡처하면 좋은지, 무엇이 반드시 보여야 하는지, 캡처 전에 무엇을 준비해야 하는지 한 번에 확인할 수 있게 구성했다.
- 권장 발표 자료는 `16:9 비율` 기준으로 준비한다.

## 공통 캡처 원칙
- 브라우저 창 크기는 가능하면 `1920 x 1080` 또는 그에 가까운 `16:9` 비율로 맞춘다.
- 브라우저 확대 비율은 `100%` 또는 `90%`로 통일한다.
- 주소창, 북마크바, OS 작업표시줄은 가능하면 보이지 않게 정리한다.
- 로그인 사용자명, 이메일 등 개인정보가 보이면 가린 뒤 캡처한다.
- 불필요한 알림, 브라우저 확장 프로그램 팝업, 개발자 도구 창은 모두 닫는다.
- 같은 발표 자료 안에서는 폰트 크기와 여백이 유사한 화면을 선택해 전체 톤을 맞춘다.
- 가능한 경우 `라이트 모드`, `깨끗한 데이터 상태`, `대표성이 있는 예시 콘텐츠`를 기준으로 캡처한다.

## 캡처 전 공통 준비
- 발표용 계정 1개를 미리 준비한다.
- 리뷰, 댓글, 찜, 컬렉션, 신고 데이터는 발표에 보일 정도로 미리 채워둔다.
- 관리자 계정도 별도로 준비한다.
- 검색 예시는 `아바타 불과재 # space adventure`처럼 개선 포인트가 드러나는 문구를 사용한다.
- 영화 상세 페이지는 예고편, 키워드, 출연진, OTT 정보가 잘 보이는 작품을 기준으로 고른다.
- 관리자 대시보드는 통계 수치와 인기 검색어가 비어 있지 않은 상태로 준비한다.

## 슬라이드별 체크리스트

### 슬라이드 1. 표지
- 추천 화면:
  - 메인 홈 화면 전체
  - 또는 영화 상세 페이지 대표 화면
- 반드시 보여야 하는 요소:
  - 서비스 이름 또는 로고 느낌이 드러나는 상단 구조
  - 영화 포스터나 콘텐츠 카드가 풍부하게 보이는 메인 영역
- 캡처 전 준비:
  - 첫 화면에서 레이아웃이 가장 안정적으로 보이는 위치로 스크롤을 맞춘다.
  - 너무 많은 텍스트보다 카드형 콘텐츠가 잘 보이는 구도를 선택한다.
- 대체안:
  - 홈 화면이 밋밋하면 영화 상세 페이지의 포스터, 제목, 예고편 영역을 대표 이미지로 사용한다.
- 권장 파일명:
  - `01_cover_home.png`

### 슬라이드 2. 개발 배경 및 문제 정의
- 추천 화면:
  - 여러 콘텐츠를 탐색하는 메인 목록 화면
  - 검색 결과 페이지 일부
- 반드시 보여야 하는 요소:
  - 다양한 영화/드라마/애니메이션 카드
  - 사용자가 콘텐츠를 비교 탐색한다는 인상을 주는 목록 구조
- 캡처 전 준비:
  - 너무 한 장르만 보이지 않도록 콘텐츠가 다양하게 노출된 위치를 선택한다.
  - 검색창이 함께 보이면 "탐색 + 검색" 구조를 설명하기 좋다.
- 대체안:
  - 메인 홈 화면과 검색 결과 화면을 작은 2분할 이미지로 넣어도 좋다.
- 권장 파일명:
  - `02_problem_exploration.png`

### 슬라이드 3. 프로젝트 목표
- 추천 화면:
  - 홈 화면
  - 검색 결과 화면
  - 상세 페이지
  - 리뷰 영역
- 반드시 보여야 하는 요소:
  - `탐색 -> 검색 -> 상세 조회 -> 리뷰/반응` 흐름을 설명할 수 있는 화면 조합
- 캡처 전 준비:
  - 이 슬라이드는 한 장 캡처보다 `3~4장 작은 썸네일 조합`이 더 적합하다.
  - 흐름이 자연스럽게 이어지도록 같은 영화 기준으로 맞추면 더 좋다.
- 대체안:
  - 화면 캡처 대신 간단한 사용자 흐름 다이어그램을 넣고, 오른쪽에 실제 화면 1장만 배치한다.
- 권장 파일명:
  - `03_goal_user_flow.png`

### 슬라이드 4. 시스템 구조 및 기술 스택
- 추천 화면:
  - 실제 서비스 화면 캡처보다는 구조도 또는 아키텍처 다이어그램
- 반드시 보여야 하는 요소:
  - `Controller -> Service -> DAO -> Mapper -> View`
  - 외부 API인 `TMDB API`, `YouTube fallback`
  - DB인 `MySQL`
- 캡처 전 준비:
  - 이 슬라이드는 화면 캡처보다 도식화 자료를 새로 제작하는 편이 낫다.
  - 발표용 도형 스타일을 통일한다.
- 대체안:
  - 코드 화면은 가능하면 피하고, 정말 필요하면 패키지 구조를 아주 작게만 보조 자료로 사용한다.
- 권장 파일명:
  - `04_system_architecture.png`

### 슬라이드 5. 핵심 기능 1. 콘텐츠 탐색
- 추천 화면:
  - 홈 화면의 인기 콘텐츠 또는 트렌딩 섹션
  - 장르별 또는 카테고리별 리스트 화면
- 반드시 보여야 하는 요소:
  - 영화, 드라마, 애니메이션처럼 범주가 구분된 구조
  - 카드형 콘텐츠 목록
- 캡처 전 준비:
  - 포스터 이미지가 균형 있게 많이 보이는 구간에서 캡처한다.
  - 한 화면에서 "탐색형 서비스" 느낌이 드는 섹션을 선택한다.
- 대체안:
  - 홈 화면 1장 + 장르 리스트 1장을 함께 배치한다.
- 권장 파일명:
  - `05_feature_discovery_home.png`
  - `05_feature_discovery_list.png`

### 슬라이드 6. 핵심 기능 2. 검색과 상세 정보
- 추천 화면:
  - 검색 결과 화면
  - 영화 상세 페이지
- 반드시 보여야 하는 요소:
  - 검색창에 `아바타 불과재 # space adventure`와 같은 입력 예시
  - 검색 결과 리스트
  - 상세 페이지의 예고편, 키워드, 출연진 또는 OTT 정보
- 캡처 전 준비:
  - 검색어 입력 상태가 보이게 유지한다.
  - 상세 페이지는 예고편 썸네일, 포스터, 제목, 키워드가 한 구도에 잘 들어오도록 위치를 조정한다.
  - 키워드 섹션이 실제로 보이는지 미리 확인한다.
- 대체안:
  - 검색 결과 화면 1장, 상세 페이지 1장을 좌우 2분할로 넣는다.
- 발표 팁:
  - 이 슬라이드는 정적 캡처만으로도 좋지만, 가능하면 라이브 데모와 가장 잘 연결되는 장이다.
- 권장 파일명:
  - `06_search_result_hashtag.png`
  - `06_detail_trailer_keyword.png`

### 슬라이드 7. 핵심 기능 3. 사용자 기능과 커뮤니티
- 추천 화면:
  - 리뷰 작성 화면
  - 리뷰/댓글이 보이는 상세 페이지 하단
  - 마이페이지 또는 컬렉션 화면
- 반드시 보여야 하는 요소:
  - 로그인 사용자 기능이 실제로 동작한다는 증거
  - 리뷰, 댓글, 좋아요, 찜, 컬렉션 중 2개 이상
- 캡처 전 준비:
  - 빈 화면이 아니라 실제 리뷰와 댓글이 보이도록 데이터를 넣어둔다.
  - 마이페이지 화면을 사용할 경우 개인정보는 가린다.
- 대체안:
  - 리뷰 화면과 컬렉션 화면을 2분할로 구성하면 커뮤니티성과 개인화 기능을 함께 보여주기 좋다.
- 권장 파일명:
  - `07_review_comment.png`
  - `07_collection_or_mypage.png`

### 슬라이드 8. 관리자 기능 및 운영 관점

- 대체안:
  - 대시보드 1장만으로 부족하면 신고 관리 화면을 작은 보조 캡처로 추가한다.

### 슬라이드 9. 개발 중 문제 해결 및 개선 사례
- 추천 화면:
  - 검색어 `#` 관련 수정 전후를 설명할 수 있는 검색 화면
  - 최근 검색어 목록이 보이는 화면
  - 영화 상세 페이지 예고편/키워드 화면
- 반드시 보여야 하는 요소:
  - 개선된 검색 입력 예시
  - 최근 검색어 또는 검색 결과 유지
  - 영화 상세 예고편과 키워드 섹션
- 캡처 전 준비:
  - 이 슬라이드는 "기능 화면"보다 "개선 결과가 드러나는 화면"을 고르는 것이 중요하다.
  - 필요하면 `Before/After` 텍스트 박스를 PPT에서 직접 덧붙인다.
- 대체안:
  - 검색 개선 사례 1장과 상세 페이지 개선 사례 1장을 나란히 배치한다.
- 발표 팁:
  - 이 슬라이드는 라이브 시연보다 정리된 캡처와 짧은 설명이 더 설득력 있다.
- 권장 파일명:
  - `09_improvement_search_fix.png`
  - `09_improvement_detail_fix.png`

### 슬라이드 10. 성과 및 향후 개선 방향
- 추천 화면:
  - 홈 화면, 검색 결과, 상세 페이지, 관리자 대시보드를 작게 모은 요약형 콜라주
- 반드시 보여야 하는 요소:
  - 프로젝트의 범위를 한 번에 보여주는 대표 화면 조합
- 캡처 전 준비:
  - 앞 슬라이드에서 사용한 대표 화면 3~4장을 다시 활용해도 충분하다.
  - 이 슬라이드는 새 화면을 찍기보다 발표 전체를 요약하는 구성이 더 중요하다.
- 대체안:
  - 화면 대신 성과 요약 아이콘형 슬라이드로 마무리해도 된다.
- 권장 파일명:

## 캡처 후 점검 체크리스트
- 화면이 너무 복잡하지 않은가
- 글자가 발표 화면에서도 읽힐 정도인가
- 핵심 기능이 한눈에 들어오는가
- 개인정보가 노출되지 않았는가
- 브라우저 주소창이나 불필요한 UI가 보이지 않는가
- 여러 장의 캡처가 비슷한 톤과 여백을 유지하는가

## Claude Desktop에 함께 넣기 좋은 요청 문장
- `첨부한 화면 캡처 체크리스트를 참고해서, 각 슬라이드에 어떤 이미지를 배치하면 좋은지 구체적으로 제안해줘`
- `슬라이드별로 가장 적절한 화면 캡처 배치 방식을 1장형, 2분할형, 콜라주형 중에서 추천해줘`
- `화면 캡처와 텍스트의 비율을 슬라이드별로 어떻게 잡으면 좋을지 알려줘`
