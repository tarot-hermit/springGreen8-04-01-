# SpringGreen8 교수님 발표 스타일 PPT 브리프

## 문서 목적
- 이 문서는 `Claude Desktop`에 첨부하여, 보다 정돈되고 학술적인 톤의 프로젝트 발표용 PPT 초안을 생성하기 위한 기준 문서다.
- 기존의 기능 나열형 소개가 아니라 `문제 정의 -> 설계 및 구현 -> 개선 사례 -> 성과와 한계`의 흐름으로 발표가 전개되도록 설계했다.
- 발표 청중은 교수님, 수업 수강생, 프로젝트 평가자를 기준으로 상정했다.
- 권장 발표 시간은 `7~10분`이다.

## 발표 톤의 방향
- 문장은 과장보다 사실 중심으로 정리한다.
- "좋다", "멋지다" 같은 표현보다 "개선했다", "구현했다", "정리했다", "검증했다" 같은 표현을 사용한다.
- 슬라이드는 화려함보다 `논리 흐름`, `기능의 필요성`, `구현 근거`가 잘 드러나게 구성한다.
- 한 장의 슬라이드에는 메시지 하나만 남기고, 발표자가 말로 보충할 수 있게 만든다.

## 프로젝트 개요
`SpringGreen8`은 영화, 드라마, 애니메이션 정보를 탐색하고, 검색 결과를 기반으로 상세 정보를 확인하며, 사용자 리뷰와 커뮤니티 반응을 함께 관리할 수 있도록 설계한 `Spring MVC 기반 콘텐츠 커뮤니티 웹 프로젝트`다.

이 프로젝트의 목적은 단순히 외부 API 데이터를 보여주는 데 그치지 않고, 실제 사용자가 콘텐츠를 탐색하고 비교하고 기록하는 흐름을 하나의 서비스 안에서 경험할 수 있도록 만드는 데 있다. 이를 위해 콘텐츠 목록 탐색, 검색, 상세 조회, 예고편 제공, 사용자 리뷰와 댓글, 컬렉션 기능, 관리자 기능까지 연결된 구조로 구현했다.

## 프로젝트 핵심 요약
- 프로젝트명: `SpringGreen8`
- 개발 형태: Java Spring MVC 웹 프로젝트
- 개발 목적: 콘텐츠 탐색과 사용자 커뮤니티 기능을 통합한 서비스 구현
- 주요 기술:
  - `Java 11`
  - `Spring MVC 4.3`
  - `JSP`
  - `JSTL`
  - `Bootstrap`
  - `jQuery`
  - `MyBatis`
  - `MySQL`
  - `TMDB API`
  - `YouTube fallback`
- 주요 기능:
  - 영화, 드라마, 애니메이션 탐색
  - 제목 및 키워드 기반 검색
  - 상세 페이지 내 예고편, 출연진, 스태프, 키워드, OTT 정보 제공
  - 회원가입, 로그인, 이메일 인증, 프로필 수정, 비밀번호 변경
  - 리뷰, 댓글, 좋아요, 신고 기능
  - 찜, 봤어요, 컬렉션 기능
  - 관리자 대시보드, 회원 관리, 리뷰 관리, 신고 처리

## 교수님 발표에서 강조하면 좋은 관점
- 이 프로젝트는 단순 CRUD 조합이 아니라 `탐색 경험`을 중심으로 여러 기능을 연결한 서비스라는 점
- 외부 API 연동 이후에도 검색 품질, 예고편 제공 안정성, 입력 검증, 관리자 데이터 구조 같은 실제 서비스 품질 문제를 개선했다는 점
- 구현뿐 아니라, 사용 중 발견된 오류와 불편을 점검하고 보완한 과정이 존재한다는 점
- 즉, "기능 구현"과 "서비스 완성도 개선"이 함께 진행된 프로젝트라는 점

## 예고편 처리 알고리즘을 발표에 넣어야 하는 이유
- 예고편 기능은 단순한 외부 API 호출이 아니라, 실제 사용성을 고려한 `다단계 탐색 로직`을 포함하고 있다.
- TMDB에 영상이 비어 있는 경우를 대비해 `언어별 재조회`, `YouTube fallback`, `캐시`, `후보 정렬`을 함께 사용한다.
- 이 부분은 단순 기능 구현보다 `서비스 안정성 확보를 위한 설계 판단`으로 설명하기 좋다.
- 교수님 발표에서는 "무엇을 만들었는가"뿐 아니라 "왜 그렇게 설계했는가"를 보여주는 사례로 활용할 수 있다.

## 예고편 처리 알고리즘 요약
- 1차로 TMDB의 한국어(`ko-KR`) 영상 목록을 조회한다.
- 결과가 비면 2차로 TMDB의 영어(`en-US`) 영상 목록을 다시 조회한다.
- 그래도 비면 3차로 이전에 저장해둔 YouTube fallback 캐시를 확인한다.
- 캐시에도 없으면 4차로 YouTube 검색 API를 사용해 제목 후보 기반 쿼리를 여러 개 생성해 탐색한다.
- 검색 쿼리는 `official trailer`, `main trailer`, `teaser`, `preview`와 같은 패턴을 조합한다.
- 드라마 시즌 영상은 `시즌 번호`, `시즌명`, `special` 여부까지 반영한 시즌 전용 검색어를 만든다.
- 후보 영상은 `쇼츠`, `리액션`, `리뷰`, `OST`, `오프닝`, `클립`, `씬 영상` 등 예고편이 아닌 결과를 제외한다.
- 남은 영상은 `제목 일치`, `채널 일치`, `official 여부`, `trailer/teaser 여부`, `시즌 일치` 점수로 정렬한다.
- 가능하면 `임베드 가능`, `public 또는 unlisted`, `KR 지역 재생 가능` 조건도 확인한다.
- 최종적으로 상위 영상만 선택하고 캐시에 저장해, 다음 요청에서는 더 빠르게 응답한다.
- 드라마 상세 페이지에서는 `선택한 시즌 -> 시즌 1 -> 시리즈 전체 영상` 순서로 한 번 더 fallback이 적용된다.

## 발표 구성 원칙
- 1장에서는 무엇을 만들었는지 명확히 말한다.
- 2장에서는 왜 이 프로젝트가 필요한지 설명한다.
- 3장에서는 어떤 사용자 흐름을 해결하려 했는지 정리한다.
- 4장에서는 시스템 구조와 기술 선택을 간결하게 설명한다.
- 5장부터 8장까지는 주요 기능을 기능군별로 나누어 설명한다.
- 9장에서는 실제로 해결한 문제와 개선 사례를 보여준다.
- 10장에서는 성과, 한계, 향후 계획으로 마무리한다.

## 추천 슬라이드 구성

### 1. 표지
- 슬라이드 제목: `SpringGreen8`
- 부제 예시: `콘텐츠 탐색과 리뷰 경험을 통합한 Spring MVC 기반 웹 서비스`
- 넣을 내용:
  - 팀명 또는 발표자명
  - 개발 기간
  - 주요 기술 키워드
- 발표 의도:
  - 프로젝트의 주제와 범위를 첫 장에서 명확하게 전달한다.
- 추천 시각 요소:
  - 메인 화면 캡처 1장
  - 또는 영화 상세 페이지 대표 화면

### 2. 개발 배경과 문제 정의
- 슬라이드 제목: `개발 배경 및 문제 정의`
- 핵심 메시지:
  - 콘텐츠 정보는 여러 플랫폼에 분산되어 있어 탐색과 비교가 비효율적이며, 사용자 반응을 함께 확인하기 어렵다.
- 설명 포인트:
  - OTT와 영화 정보가 분산되어 있음
  - 제목 검색만으로는 사용자가 원하는 콘텐츠를 찾기 어려운 경우가 있음
  - 단순 줄거리 조회가 아니라, 예고편, 리뷰, 키워드, 사용자 반응까지 함께 보는 흐름이 필요함
- 발표 의도:
  - 프로젝트가 단순히 "만들 수 있어서 만든 것"이 아니라, 명확한 사용자 불편에서 출발했다는 점을 보여준다.

### 3. 프로젝트 목표와 범위
- 슬라이드 제목: `프로젝트 목표`
- 핵심 메시지:
  - 콘텐츠 탐색, 검색, 상세 조회, 커뮤니티 기능을 하나의 흐름으로 통합하는 웹 서비스를 구현하는 것이 목표였다.
- 설명 포인트:
  - 다양한 콘텐츠 유형을 하나의 서비스에서 탐색 가능하게 구성
  - 외부 API 기반 콘텐츠 정보를 사용자 기능과 연결
  - 관리자 기능까지 포함해 서비스 운영 구조를 갖추도록 설계
- 발표 의도:
  - 프로젝트의 범위가 어디까지인지, 어떤 수준을 목표로 했는지 명확히 한다.

### 4. 시스템 구조와 기술 스택
- 슬라이드 제목: `시스템 구조 및 기술 스택`
- 핵심 메시지:
  - 전통적인 Spring MVC 구조를 기반으로, 역할 분리와 유지보수성을 고려해 설계했다.
- 설명 포인트:
  - Frontend: `JSP`, `JSTL`, `Bootstrap`, `jQuery`
  - Backend: `Spring MVC`, `Java 11`
  - Data Layer: `MyBatis`, `MySQL`
  - External Data: `TMDB API`, `YouTube fallback`
  - 계층 구조: `Controller -> Service -> DAO -> Mapper -> View`
- 발표 의도:
  - 구현 기술을 나열하는 것이 아니라, 왜 이러한 구조가 적절했는지 설명하는 장으로 사용한다.
- 추천 시각 요소:
  - 간단한 시스템 구조도

### 5. 핵심 기능 1: 콘텐츠 탐색
- 슬라이드 제목: `핵심 기능 1. 콘텐츠 탐색`
- 핵심 메시지:
  - 사용자가 영화, 드라마, 애니메이션을 카테고리와 흐름에 따라 직관적으로 탐색할 수 있도록 구성했다.
- 설명 포인트:
  - 인기 콘텐츠, 트렌딩, 현재 상영작, 개봉 예정작 제공
  - 영화, 드라마, 애니메이션 탭 분리
  - 장르 기반 접근 가능
- 발표 의도:
  - 사용자의 첫 진입 경험을 설명하는 슬라이드로 활용한다.
- 추천 시각 요소:
  - 홈 화면 캡처
  - 카테고리 리스트 화면 캡처

### 6. 핵심 기능 2: 검색과 상세 정보
- 슬라이드 제목: `핵심 기능 2. 검색과 상세 정보`
- 핵심 메시지:
  - 검색 정확도와 상세 정보 접근성을 높여 사용자가 원하는 콘텐츠에 빠르게 도달할 수 있도록 했다.
- 설명 포인트:
  - 제목 검색과 키워드 검색을 함께 지원
  - `# 키워드` 입력 지원
  - 오타 및 띄어쓰기 보정 로직 적용
  - 상세 페이지에서 예고편, 출연진, 스태프, 키워드, OTT 제공처 확인 가능
  - 예고편은 TMDB 조회 실패 시 YouTube fallback과 후보 정렬 알고리즘으로 보완
- 발표 의도:
  - 사용성 개선이 가장 두드러지는 부분으로, 실제 서비스 품질 향상 사례를 보여준다.
- 추천 시각 요소:
  - 검색 결과 화면
  - 영화 상세 페이지

### 7. 핵심 기능 3: 사용자 기능과 커뮤니티
- 슬라이드 제목: `핵심 기능 3. 사용자 기능과 커뮤니티`
- 핵심 메시지:
  - 콘텐츠 소비 이후의 반응과 기록까지 서비스 안에서 이어질 수 있도록 구현했다.
- 설명 포인트:
  - 회원가입, 로그인, 이메일 인증
  - 프로필 수정, 비밀번호 변경
  - 리뷰 작성, 댓글, 좋아요, 신고
  - 찜, 봤어요, 컬렉션
- 발표 의도:
  - 단순 정보 제공이 아니라 사용자 참여형 서비스라는 점을 강조한다.
- 추천 시각 요소:
  - 리뷰 작성 화면
  - 마이페이지 또는 컬렉션 화면

### 8. 관리자 기능
- 슬라이드 제목: `관리자 기능 및 운영 관점`
- 핵심 메시지:
  - 사용자 기능뿐 아니라 실제 운영을 가정한 관리 기능도 함께 구현했다.
- 설명 포인트:
  - 관리자 대시보드
  - 회원 관리
  - 리뷰 관리
  - 신고 처리
  - 인기 검색어 및 통계 확인
- 발표 의도:
  - 프로젝트가 사용자 화면 중심에서 끝나지 않고, 운영 측면까지 고려했다는 점을 보여준다.
- 추천 시각 요소:
  - 관리자 대시보드 화면 캡처

### 9. 문제 해결 및 개선 사례
- 슬라이드 제목: `개발 중 문제 해결 및 개선 사례`
- 핵심 메시지:
  - 구현 이후 발견된 사용성 문제와 구조적 문제를 점검하고 개선했다.

  - `#` 포함 검색어의 페이지 이동 오류 수정

  - 예고편 후보를 필터링하고 점수화해 실제 예고편에 가까운 영상만 남기도록 정리
  - 영화 상세 페이지에 키워드 섹션 연결
  - 입력 검증 규칙 통합
  - XSS/SQL 과탐 완화
- 발표 의도:
  - 개발 과정에서의 디버깅 능력과 유지보수성을 함께 보여줄 수 있다.

### 선택 슬라이드. 예고편 처리 알고리즘
- 슬라이드 제목: `예고편 처리 알고리즘`
- 핵심 메시지:
  - 예고편 기능은 단순 조회가 아니라, 여러 단계의 fallback과 후보 평가 로직으로 안정성을 확보했다.
- 설명 포인트:
  - `TMDB ko-KR -> TMDB en-US -> YouTube 캐시 -> YouTube 검색` 순 fallback
  - 예고편이 아닌 쇼츠, 리뷰, OST, 클립 영상 제외
  - 제목 일치, official 여부, trailer/teaser 여부, 시즌 일치로 점수화
  - 재생 가능 여부와 지역 제한까지 확인
  - 최종 결과 캐시 저장
- 발표 의도:
  - 기술적으로 가장 차별화되는 구현 포인트를 별도 슬라이드로 보여주고 싶을 때 사용한다.
- 추천 시각 요소:
  - 간단한 흐름도
  - fallback 단계 다이어그램

### 10. 성과, 한계, 향후 계획
- 슬라이드 제목: `성과 및 향후 개선 방향`
- 핵심 메시지:
  - 기능 통합과 서비스 흐름 구현에는 의미 있는 성과가 있었으며, 향후에는 개인화와 자동화 영역으로 확장할 수 있다.
- 설명 포인트:
  - 탐색, 검색, 상세 조회, 커뮤니티, 관리자 기능까지 통합
  - 검색 품질과 예고편 제공 안정성 개선
  - 입력 검증 및 운영 데이터 구조 정리
  - 향후 과제:
    - 추천 알고리즘 고도화
    - 리뷰 기반 개인화
    - 반응형 UI 강화
    - 통합 테스트 및 배포 자동화
- 발표 의도:
  - 현재 성과를 정리하되, 한계를 인지하고 다음 과제를 제시하는 방식으로 마무리한다.

## PPT 제작 시 추천 디자인 방향
- 배경은 흰색 또는 매우 밝은 회색 계열을 사용한다.
- 포인트 컬러는 하나만 사용하고, 초록 계열 또는 짙은 핑크 계열처럼 명확한 색을 선택한다.
- 아이콘과 도형은 최소한으로 사용하고, 기능 설명은 실제 화면 캡처로 보완한다.
- 텍스트는 문장형보다 짧은 명사형 중심으로 정리한다.
- 한 슬라이드에 요소를 너무 많이 배치하지 않는다.

- 관리자 대시보드 화면
